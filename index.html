01 · Problem Discovery

核心问题集中在“教学过程如何被控制”

数学辅导场景中，大模型具备较强的解题与解释能力，产品体验仍取决于它能否理解学生当前卡点，并在每一轮控制合适的信息量。

1

答案出现过早

模型获得题目后容易直接输出完整答案和解法，学生缺少观察条件、建立关系和自主计算的过程。

产品要求：控制答案与关键步骤的展示时机。
2

学生卡点判断不足

同一句“不会”可能对应读题困难、概念不清、列式错误或计算卡住，统一提示无法持续推进解题。

产品要求：先判断学习状态，再决定下一步教学动作。
3

状态与情绪相互干扰

学生的学习进度决定提示难度，畏难、犹豫等文本情绪影响表达方式，两类信号需要承担不同职责。

产品要求：教学难度与回复语气采用独立控制变量。
产品目标：让 Agent 每一轮都基于题目正确解法、学生当前状态和文本情绪，选择合适的教学动作。核心判断由结构化节点完成，最终回复节点负责把策略转成学生可理解的语言。
02 · Product Strategy

首期聚焦三项 P0 能力

MVP 围绕一条完整教学闭环展开：理解题目、获得稳定解法、根据学生表现决定下一轮引导。

P0 · Question Understanding

题目结构化

统一处理文字输入与题图识别结果，提取题干、题型、选项、年级、学科、难度与可解性，为下游节点提供稳定输入。

P0 · Reasoning

内部独立求解

Logic_Solver 生成最终答案、解法、步骤、关键点与常见错误，提供一条完整且可复用的标准解题路径。

P0 · Teaching Decision

动态教学决策

根据学生状态选择追问、提示、纠错或拆解任务，再结合文本情绪调整回复语气，持续推动当前解题步骤。

先求解，再教学先得到稳定解题路径，再决定学生这一轮需要看到的信息。
状态与情绪分工学生状态控制提示等级，文本情绪控制表达方式。
生成放在最后教学动作先结构化确定，最终节点再生成自然语言回复。
03 · Agent Workflow

结构化教学决策工作流

每个节点只承担一类判断任务，前一节点的结构化输出成为后一节点的决策依据。

INPUT

图片 / 文本输入

接收题图、题目文本和学生多轮回复。

输入统一进入题目检查。
QUESTION_CHECK

题目检查

提取题型、题干、选项、年级、学科、难度、题目域和可解性。

信息不足时输出补充问题与原因。
LOGIC_SOLVER

逻辑求解

内部完成题目求解并拆分完整解题路径。

输出答案、方法、步骤、关键点和常见错误。
STUDENT_STATE

学生状态

结合学生回答与解题步骤，判断理解程度和当前卡点。

决定下一轮提示难度。
EMOTION

文本情绪

从学生表达中判断正常、犹豫、畏难或挫败等信号。

决定回复表达方式。
TEACHING_STRATEGY

教学策略

综合当前步骤、学生状态和情绪，选择追问、提示、纠错或任务拆分。

明确这一轮允许展示的信息边界。
RESPONSE

回复生成

将确定后的教学策略转换成自然、简洁、符合学习阶段的回复。

保持一次只推进一个关键任务。
CONTEXT

上下文更新

记录已确认信息、已完成步骤和下一步目标，作为下一轮判断依据。

减少重复追问与上下文漂移。
节点职责：Question_Check 保证题目可用；Logic_Solver 保证解题正确；Student_State 决定教学难度；Emotion 决定表达语气；Teaching_Strategy 负责教学动作；Response 负责最终语言组织。
04 · Decision Mechanism

解题层与教学层独立决策

完整解题结果作为内部参考，学生可见内容由教学层根据当前状态进行裁剪和组织。

R

Reasoning Layer · Logic_Solver

建立稳定的标准解题路径，为每一轮教学判断提供统一依据。

solver_status · 当前求解状态
final_answer · 最终答案
solution_method · 解题方法
solution_steps · 结构化步骤
key_points / common_errors · 关键点与常见错误
T

Teaching Layer · Strategy

读取内部解法与学生表现，决定这一轮的教学动作和可见信息。

当前位于哪一个解题步骤
学生已经正确理解了哪些信息
下一轮采用追问、提示、纠错或任务拆解
本轮允许展示到哪一级提示
结合文本情绪调整语气和句式
同一道题保持一条稳定解题路径，教学层根据学生每一轮表现动态改变可见信息。

学生状态 → 教学难度

判断学生能否推进当前步骤，决定提示强度。

自主推进开放式追问，让学生继续表达思路。
方向正确但卡住提供一级提示，聚焦题目条件。
理解或列式错误定位错误点并进行局部纠偏。
完全无法推进拆小任务并逐级增加提示信息。

文本情绪 → 回复语气

识别表达中的情绪信号，调整语言节奏和互动压力。

正常保持简洁、直接的教学表达。
犹豫降低回答门槛，鼓励先说部分思路。
畏难缩小任务范围，减少一次需要处理的信息量。
挫败先缓和表达，再回到一个可完成的小步骤。
学生状态控制“教到什么程度”，文本情绪控制“这一轮怎么说”。
05 · Interaction Strategy

提示信息按学生推进情况逐级释放

每轮只推进一个关键认知任务，学生连续无法推进时再增加提示强度。

四级提示策略

教学策略节点根据学生状态选择提示等级，并控制最终回复中可出现的信息量。

一级提示引导学生重新关注已知条件和目标问题。
二级提示提示需要使用的数量关系、概念或运算方向。
三级提示帮助学生建立算式或完成局部推导。
解释兜底解释关键步骤，同时保留计算或方法总结任务。
学生我不会，这道题太难了。
Agent我们先只看第一步。题目一共告诉了你几个数量？
学生好像有两个，一个是总数，一个是每组的数量。
Agent对，这两个信息已经找到了。知道总数和每组数量，要计算组数应该用什么运算？

策略变化：学生状态触发任务拆分，畏难情绪触发低压力表达，回复仍围绕当前解题步骤推进。

06 · Workflow Refactor

工作流重构围绕三处职责拆分展开

重构重点是减少单节点自由判断，把关键产品规则转成明确的数据结构和节点职责。

题目处理结构化

题目内容直接进入下游推理，输入格式和完整性不稳定。
↓
Question_Check 先输出统一题目对象，并单独判断 can_solve 与补充信息需求。

下游节点读取相同字段，降低题目识别问题向整条链路传递的概率。

解题与教学解耦

同一个生成过程同时负责算题、判断学生状态和组织回复。
↓
Logic_Solver 保存完整内部解法，Teaching_Strategy 单独决定本轮展示内容。

稳定解法成为教学决策基线，提示等级变化不会改变题目的标准推理路径。

状态与情绪分开

“不会”“太难”“算错”等表达被放在同一判断逻辑中处理。
↓
Student_State 判断学习进度，Emotion 判断文本情绪，两类结果分别控制难度与语气。

同一学习状态可以采用不同表达方式，同一情绪也可以匹配不同教学动作。

07 · Bad Case Iteration

Bad Case 直接映射到工作流节点

问题归因落到具体节点后，优化动作从修改整段提示词转向调整输入结构、节点职责和策略规则。

Bad Case问题归因对应节点重构动作
题图信息缺失题干、数字或单位不完整时继续向下推理。Question_Check增加 can_solve 判断；信息不足时生成明确的补充问题和原因。
过早给出答案求解结果与学生可见回复缺少信息边界。Logic_Solver + Teaching_Strategy完整答案保留在内部求解结果中，教学策略按提示等级决定本轮可展示内容。
重复追问已确认信息、已完成步骤和当前目标没有稳定进入下一轮判断。Context + Student_State每轮更新已知信息和当前步骤，下一轮从未完成任务继续推进。
“不会”后仍重复原问题学生无法推进时没有触发教学难度调整。Student_State将无法推进映射到任务拆分和更高提示等级，缩小单轮认知任务。
畏难表达处理生硬学习状态与表达情绪使用同一策略变量。Emotion + Response保留原教学目标，根据文本情绪调整语气、句式和回答门槛。
08 · My Role

从产品规则到 Agent 节点的完整设计

项目工作覆盖需求拆解、工作流结构、数据契约、提示策略和多轮交互设计。

01

需求与场景拆解

围绕答案泄露、学生卡点和多轮交互问题，明确教学过程中需要被产品控制的关键变量。

02

Agent 工作流设计

拆分 Question_Check、Logic_Solver、Student_State、Emotion、Teaching_Strategy 与 Response 等节点职责。

03

结构化数据契约

为题目检查和逻辑求解定义稳定输出字段，让节点间通过结构化对象传递信息。

04

教学策略设计

建立状态驱动的提示等级和情绪驱动的回复语气规则，控制单轮信息量与互动节奏。

PROJECT TAKEAWAY

Agent 产品设计的核心是把关键判断变成可控的决策链

这个项目通过题目结构化、独立求解、学生状态识别、文本情绪识别和教学策略拆分，把一次自由生成拆成多个职责明确的节点。每个节点只解决一类问题，结构化输出继续驱动下一步决策。

Question_Check 负责保证题目输入可用，减少错误输入沿工作流传播。
Logic_Solver 提供稳定的内部解题基线，教学层控制学生每轮可见的信息量。
学生状态与文本情绪分别控制教学难度和回复语气，让多轮互动保持连续。
